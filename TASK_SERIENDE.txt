================================================================================
WICHTIGE KONZEPTE
================================================================================

1. SSR fuer Artikel-Seiten
   ----------------------
   Express SSR Server rendert React-Komponenten server-side:
   
   GET /:slug
   -> Backend holt Artikel aus MongoDB
   -> Express rendert <ArticlePage article={data} /> zu HTML
   -> Server-side rendering mit vollstaendigem HTML
   -> Client hydrated React App
   
   Ergebnis:
   - Google sieht vollstaendigen Content (nicht nur <div id="root">)
   - Schnelles First Contentful Paint
   - SEO-optimiert

2. ISR-aehnliches Caching
   ----------------------
   Redis cached gerenderte HTML-Seiten:
   
   Cache-Key: page:/artikel-slug
   TTL: 300 Sekunden (5 Minuten)
   
   Flow:
   1. Request kommt: GET /artikel-slug
   2. Pruefe Redis: Gibt es page:/artikel-slug?
   3. JA -> Return cached HTML (schnell!)
   4. NEIN -> Render SSR -> Cache in Redis -> Return HTML
   
   Bei Artikel-Update:
   - DELETE page:/artikel-slug aus Redis
   - Naechster Request generiert neuen Cache

3. Google News Sitemap
   -------------------
   /news-sitemap.xml zeigt nur Artikel der letzten 48 Stunden:
   
   MongoDB Query:
   db.articles.find({
     published_at: { $gte: new Date(Date.now() - 48*60*60*1000) }
   })
   
   XML Format:
   <url>
     <loc>https://serien.de/artikel-slug</loc>
     <news:news>
       <news:publication_date>2024-01-15T10:00:00Z</news:publication_date>
       <news:title>Artikel Titel</news:title>
     </news:news>
   </url>

API ENDPOINTS (Backend)
================================================================================

POST   /api/articles              # Artikel erstellen
GET    /api/articles              # Alle Artikel (paginated)
GET    /api/articles/:id          # Einzelner Artikel
PUT    /api/articles/:id          # Artikel updaten
DELETE /api/articles/:id          # Artikel loeschen

GET    /api/series/:tmdb_id       # Series Daten von TMDB
GET    /api/sitemap               # Sitemap Daten
GET    /api/news-sitemap          # News Sitemap Daten (48h)

TESTING CHECKLISTE

1. SSR funktioniert:
   -----------------
   curl http://localhost:3000/test-artikel
   
   Erwarte:
   - Status 200
   - HTML Response (nicht JSON)
   - Vollstaendiger HTML Content sichtbar (nicht nur <div id="root">)
   - <title>-Tag mit Artikel-Titel
   - JSON-LD Schema im <head>

2. Cache funktioniert:
   -------------------
   # Erster Request (Cache Miss)
   time curl http://localhost:3000/test-artikel
   # Erwarte: ~200ms
   
   # Zweiter Request (Cache Hit)
   time curl http://localhost:3000/test-artikel
   # Erwarte: ~20ms (10x schneller!)
   
   # Pruefe Redis:
   redis-cli KEYS "page:*"
   # Erwarte: page:/test-artikel

3. Sitemaps gueltig:
   -----------------
   curl http://localhost:3000/sitemap.xml
   # Erwarte: Valid XML mit allen Artikeln
   
   curl http://localhost:3000/news-sitemap.xml
   # Erwarte: Valid XML, nur Artikel < 48h

   # https://www.xml-sitemaps.com/validate-xml-sitemap.html
